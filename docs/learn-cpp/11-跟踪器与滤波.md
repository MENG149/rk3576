# 11 — 跟踪器与滤波：从"帧帧找"到"追着走"

## 为什么不能只靠检测

前面 RKNN 检测 + ROI 精修，每帧都能找到一个精确的矩形。看起来够用了，对吧？

先想一个问题：**如果某一帧没检测到呢？**

目标可能被短暂遮挡（飞过一片树）、可能图像突然模糊（相机抖动）、可能 NPU 推理偶尔漏检。只靠逐帧检测的话，漏一帧输出就断了——你的系统就不知道该往哪瞄准了。

跟踪器干的就是这事：**给目标的位置和速度建立一个"信念"，即使偶尔几帧没看到目标，也能根据之前的运动趋势继续预测它在哪里，保持输出不中断。**

本章对应文件：`tracker.hpp` + `tracker.cpp`。

---

## 跟踪器在管线中的位置

```
相机帧 → RKNN检测 → (可选)ROI精修 → Tracker → AimWriter → 串口/标准输出
                         ↓               ↓
                    PriorBox ←──── 跟踪器提供先验框给下一轮检测
```

注意那个回环箭头：跟踪器不仅消费检测结果，还会把预测的位置作为"先验框"（PriorBox）反馈给检测器，告诉检测器"我猜目标大概在这个区域，你优先在这附近找"。这是一个协同设计——检测器和跟踪器互相帮助。

## α-β 滤波器：用大白话理解

先放下代码，讲清楚这个概念。α-β 滤波器是整个跟踪器的心脏，理解它后面代码就全通了。

### 问题设定

你有一个移动的目标，你每隔一段时间（比如 16.7ms，60fps）收到一个它的位置测量值。但测量值有噪声（RKNN 检测的坐标不准，会有上下跳动）。

你同时有两个信息源：

1. **模型预测**：根据上一帧的估计位置 + 估计速度，算出"如果匀速运动，目标现在应该在哪儿"
2. **新测量**：这一帧检测器告诉你"目标在这儿"

两个信息源都不完美——预测可能不准（目标加速了、减速了），新测量也有噪声。α-β 滤波器就是告诉你**怎么把这两个信息源融合起来，得到一个比两者都准的估计**。

### α：位置的信任度

```cpp
// track_alpha = 0.55
x_ = px + config_.track_alpha * rx;
```

翻译成大白话：

```
新估计位置 = 模型预测位置 + α × (测量位置 - 模型预测位置)
```

这里 `(测量位置 - 模型预测位置)` 叫"残差"（residual，代码里变量名叫 `rx`/`ry`），意思是"测量值和预测值差了多少"。

- **α = 0**：完全不信测量值，新估计 = 模型预测位置。不管检测器说啥你都不信，纯靠惯性滑行。位置非常平滑但严重滞后。
- **α = 1**：完全信任测量值，新估计 = 这次检测到的位置。测量噪声100%进入输出，位置跳动很大。
- **α = 0.55**（你的项目）：55% 信新测量，45% 信模型预测。既跟得上目标的真实移动，又不会被噪声带着乱跳。

**直观理解**：α 越大，输出越"灵敏"但越"抖"；α 越小，输出越"平滑"但越"迟钝"。0.55 是一个偏向灵敏的平衡值——电赛场景目标变化快，宁肯灵敏点也别滞后。

### β：速度的学习率

```cpp
// track_beta = 0.20
vx_ += config_.track_beta * rx / dt_safe;
```

翻译成大白话：

```
新速度 = 旧速度 + β × (这次位置的残差 ÷ 时间间隔)
```

为什么是"残差 ÷ 时间间隔"？因为残差是位置的偏差，除以时间就是速度偏差——意思是"这次预测错了，说明我估计的速度可能不准，要修正"。

- **β = 0**：完全不学新速度。不管你目标加速还是减速，速度永远保持不变。
- **β = 1**：残差全部算进速度里。目标一抖动，速度估计就天翻地覆。
- **β = 0.20**（你的项目）：只把 20% 的残差算进速度修正。速度变化比较平滑。

**β 通常比 α 小**——速度估计应该比位置估计更保守。位置可以快速跟上，但速度要用更多帧来确认。一个突然的噪声点如果直接变成速度，下一帧的预测就飞了。

### box_alpha：边界框尺寸的平滑

位置和速度之外，目标的大小（边界框的宽和高）也需要平滑：

```cpp
// track_box_alpha = 0.45
w_ = (1.0f - config_.track_box_alpha) * w_ + config_.track_box_alpha * new_w;
h_ = (1.0f - config_.track_box_alpha) * h_ + config_.track_box_alpha * new_h;
```

这是**指数移动平均**（EMA）。公式等价于：

```
新尺寸 = 55% × 旧尺寸 + 45% × 新测量尺寸
```

框的尺寸变化比位置慢，所以用 0.45 比位置 α 小一点，更平滑。

### 三个 α/β 总结

| 参数 | 默认值 | 作用于 | 越大越… |
|------|--------|--------|---------|
| `track_alpha` | 0.55 | 位置（x, y） | 灵敏、跟得紧，但可能抖 |
| `track_beta` | 0.20 | 速度（vx, vy） | 速度变化快，但容易被噪声带偏 |
| `track_box_alpha` | 0.45 | 边界框尺寸（w, h） | 尺寸变化快，但可能忽大忽小 |

## RectTracker 状态机

跟踪器有三种状态，像红绿灯一样切换：

```
   新目标出现
      ↓
  SEARCHING ──→ 收到连续检测 ──→ LOCKED
      ↑                            │
      │        连续丢 3 帧           │
      └──────────── LOST ←──────────┘
                      │
                      │ 再连续丢 3 帧 (总共丢 N 帧 ≥ max_predict_misses)
                      ↓
                  SEARCHING
```

对应的成员变量：

```cpp
  bool initialized_ = false;    // 是否收到过第一帧数据
  int misses_ = 1000;           // 连续丢帧计数（初始1000表示从未跟踪）
  std::string state_ = "SEARCHING";  // 当前状态
```

**状态转换规则**：

1. **SEARCHING**：初始状态。没有目标信息，不给外部输出任何位置。收到新的检测结果后，直接初始化位置和速度（把测量值当初始值，速度设 0），进入 LOCKED 状态。

2. **LOCKED**：有稳定的跟踪。正常收到检测结果（`Update` 函数被调用）时，用 α-β 滤波更新。没有收到但用 `Predict` 纯预测时，状态保持在 LOCKED 或先进入 LOST（取决于调用 `Predict` 还是 `MarkDetectMiss`）。

3. **LOST**：连续丢帧但还没彻底丢失。继续用匀速模型预测位置，但置信度每帧衰减（`conf_ *= 0.97`）。如果丢帧数超过 `max_predict_misses`（默认 3 帧），回到 SEARCHING。

## ApplyMeasurement：核心滤波函数

这是跟踪器最重要的函数，所有更新都走这里：

```cpp
void RectTracker::ApplyMeasurement(const Box& box, const cv::Point2f& center,
                                   float conf, int count, double timestamp,
                                   const cv::Size& frame_size,
                                   const std::string& source) {
```

### 分支1：初始化（首次跟踪或重新锁定）

```cpp
  const float new_w = BoxWidth(box);
  const float new_h = BoxHeight(box);
  const double dt = StepDt(timestamp);

  if (!initialized_ || misses_ > config_.max_predict_misses) {
    x_ = center.x;
    y_ = center.y;
    vx_ = 0.0f;
    vy_ = 0.0f;
    w_ = new_w;
    h_ = new_h;
    initialized_ = true;
```

触发条件：`!initialized_`（从未初始化过）**或** `misses_ > max_predict_misses`（丢帧太久，之前的跟踪信息不可信了）。

此时的做法：直接把测量位置和尺寸设为当前估计值，速度清零。没有历史信息可参考，就全信新的测量。

### 分支2：连续跟踪（α-β 滤波）

```cpp
  } else {
    const float px = x_ + vx_ * static_cast<float>(dt);   // ① 用上帧速度预测当前位置
    const float py = y_ + vy_ * static_cast<float>(dt);
    const float rx = center.x - px;                        // ② 计算残差（测量 - 预测）
    const float ry = center.y - py;

    x_ = px + config_.track_alpha * rx;                   // ③ 位置修正
    y_ = py + config_.track_alpha * ry;
    const float dt_safe = static_cast<float>(std::max(1e-3, dt));
    vx_ += config_.track_beta * rx / dt_safe;              // ④ 速度修正
    vy_ += config_.track_beta * ry / dt_safe;
    w_ = (1.0f - config_.track_box_alpha) * w_             // ⑤ 尺寸平滑
         + config_.track_box_alpha * new_w;
    h_ = (1.0f - config_.track_box_alpha) * h_
         + config_.track_box_alpha * new_h;
```

逐步翻译：

1. **预测**：假设目标匀速运动，用上一帧的位置和速度推算这一帧的位置。`px = x_ + vx_ * dt`。
2. **残差**：这一帧检测到的位置和预测的位置差了多少。`rx`/`ry` 告诉我们"猜偏了多
   远"。
3. **位置修正**：不直接跳到测量值，也不停在预测值，而是取加权平均。α=0.55 意味着 55% 相信测量值，45% 相信预测值。
4. **速度修正**：用残差和时间差修正速度估计。`dt_safe` 防止除以 0（下限 0.001 秒）。
5. **尺寸平滑**：用指数移动平均平滑宽高。

### 收尾

```cpp
  Clamp(frame_size);     // 限制坐标不超出画面
  misses_ = 0;           // 重置丢帧计数
  conf_ = conf;          // 更新置信度
  count_ = count;        // 更新检测候选数
  state_ = "LOCKED";     // 稳定跟踪中
  source_ = source;      // 标记数据来源
```

每次收到检测数据都重置 `misses_` 并设状态为 `LOCKED`。

## Predict：纯预测模式

```cpp
void RectTracker::Predict(double timestamp, const cv::Size& frame_size) {
  if (!initialized_) {
    state_ = "SEARCHING";
    source_ = "none";
    return;
  }
  const double dt = StepDt(timestamp);
  x_ += vx_ * static_cast<float>(dt);    // 匀速外推
  y_ += vy_ * static_cast<float>(dt);
  Clamp(frame_size);
  if (misses_ > 0) {
    state_ = "LOST";
    source_ = "predict";
    conf_ *= 0.97f;                       // 置信度每帧衰减 3%
  }
}
```

当没有新检测结果但还想输出位置时，调用 `Predict`。它用匀速模型（位置 = 之前的位置 + 速度 × 时间）往外推。

如果连续预测且已经有丢帧记录（`misses_ > 0`），状态变成 `LOST`，置信度每帧乘 0.97（衰减 3%）。这个衰减意味着：预测越久，越不靠谱。预测了 10 帧（约 0.17 秒）后，置信度已经只剩 `0.97^10 ≈ 0.74`，输出设备可以据此决定要不要降权。

## MarkDetectMiss：标记丢帧

```cpp
void RectTracker::MarkDetectMiss(double timestamp, const cv::Size& frame_size) {
  if (!initialized_) {
    state_ = "SEARCHING";
    source_ = "none";
    return;
  }
  ++misses_;                         // 丢帧计数 +1
  Predict(timestamp, frame_size);    // 先预测一下，保证位置有值
  if (misses_ > config_.max_predict_misses) {   // 超过阈值（默认 3）
    state_ = "SEARCHING";            // 回滚到搜索状态
    source_ = "none";
    conf_ = 0.0f;
    count_ = 0;
  }
}
```

`MarkDetectMiss` 和 `Update` 是互斥的——每帧要么调 `Update`（有检测结果），要么调 `MarkDetectMiss`（没检测到）。它做的事情：

1. 丢帧计数加一
2. 用 `Predict` 匀速外推，保证位置有值
3. 如果连续丢帧超过 `max_predict_misses`（默认 3 帧），彻底放弃跟踪，回到 SEARCHING

## PriorBox：给 RKNN 提供搜索区域

```cpp
std::optional<Box> RectTracker::PriorBox() const {
  if (!initialized_ || misses_ > config_.max_predict_misses) {
    return std::nullopt;
  }
  return Box{x_ - w_ * 0.5f, y_ - h_ * 0.5f, x_ + w_ * 0.5f, y_ + h_ * 0.5f};
}
```

这个函数返回"目标可能在的矩形区域"，给检测器当先验信息。

如果跟踪器正常工作（已初始化且没丢太多帧），就给一个以当前估计位置为中心、以当前估计尺寸为大小的矩形。检测器可以用这个矩形来做"注意力聚焦"——优先在这个区域内找目标。

如果跟踪器还没初始化或丢失太久，返回 `std::nullopt`，检测器就知道"没有先验信息，全图搜索吧"。

这就是前面画的那个回环：
```
检测器输出 → 跟踪器 → PriorBox → 检测器下一轮的搜索偏好
```

## Snapshot：对外只暴露结构体

```cpp
TrackSnapshot RectTracker::Snapshot() const {
  TrackSnapshot snapshot;
  snapshot.active = initialized_ && misses_ <= config_.max_predict_misses;
  snapshot.misses = misses_;
  snapshot.state = snapshot.active ? state_ : "SEARCHING";
  snapshot.source = snapshot.active ? source_ : "none";
  snapshot.conf = snapshot.active ? conf_ : 0.0f;
  snapshot.count = snapshot.active ? count_ : 0;
  if (snapshot.active) {
    snapshot.center = cv::Point2f(x_, y_);
    snapshot.box = Box{x_ - w_ * 0.5f, y_ - h_ * 0.5f,
                       x_ + w_ * 0.5f, y_ + h_ * 0.5f};
  }
  return snapshot;
}
```

这个设计模式叫"对外只暴露结构体"——`TrackSnapshot` 是一个简单结构体（在 types.hpp 里定义），只包含对外有意义的信息：

```cpp
struct TrackSnapshot {
  bool active = false;      // 是否有效
  Box box;                  // 边界框
  cv::Point2f center;       // 中心
  float conf = 0.0f;        // 置信度
  int count = 0;            // 检测候选数
  int misses = 0;           // 连续丢帧数
  std::string state;        // "SEARCHING" / "LOCKED" / "LOST"
  std::string source;       // "rknn" / "refine" / "predict" / "none"
};
```

而 `RectTracker` 内部有 `vx_`, `vy_`, `last_timestamp_` 这些实现细节，外部根本不需要知道——暴露出去只会让调用方困惑。`Snapshot()` 读的是成员变量，返回的是结构体，做了一层"翻译"。

如果你要在 `main.cpp` 里拿到跟踪结果写入串口，你调用的是：

```cpp
auto snapshot = tracker.Snapshot();
// snapshot.active → 判断是不是有效跟踪
// snapshot.center → 瞄准用
// snapshot.box   → 显示用
// snapshot.conf  → 置信度
```

你永远不需要关心 `tracker.vx_` 或者 `tracker.last_timestamp_`。

## StepDt：时间差计算与钳位

```cpp
double RectTracker::StepDt(double timestamp) {
  if (last_timestamp_ <= 0.0) {
    last_timestamp_ = timestamp;
    return 1.0 / 60.0;          // 第一帧，假设 60fps
  }
  const double dt = std::clamp(timestamp - last_timestamp_, 1e-3, 0.25);
  last_timestamp_ = timestamp;
  return dt;
}
```

这个函数有三个细节值得讲：

1. **第一帧**（`last_timestamp_ <= 0`）：还没历史，不知道时间间隔，假设是 60fps 的 16.7ms。
2. **`std::clamp(value, min, max)`**：C++17 的函数，把值限制在 [min, max] 区间内。这里限制 dt 在 [0.001, 0.25] 秒之间。
3. **钳位的意义**：
   - 下限 1ms（1e-3）：防止 dt=0 导致除以 0（速度修正那里 `rx / dt_safe`）
   - 上限 250ms（0.25）：防止系统卡顿后突然跑一个大时间差，然后 `vx_ * dt` 直接飞出一个天文数字，把预测位置推到画面外

## Clamp：边界限制

```cpp
void RectTracker::Clamp(const cv::Size& frame_size) {
  x_ = ClampFloat(x_, 0.0f, static_cast<float>(std::max(0, frame_size.width - 1)));
  y_ = ClampFloat(y_, 0.0f, static_cast<float>(std::max(0, frame_size.height - 1)));
  w_ = ClampFloat(w_, 1.0f, static_cast<float>(std::max(1, frame_size.width)));
  h_ = ClampFloat(h_, 1.0f, static_cast<float>(std::max(1, frame_size.height)));
}
```

跟踪器的预测可能会把位置推到画面外面去（比如目标向左飞出画面，速度向左，预测位置 x 变成负数）。`Clamp` 在每次更新和预测后都会调用一次，确保估计位置始终在画面内。

`ClampFloat` 是在 types.hpp 里定义的：

```cpp
inline float ClampFloat(float value, float low, float high) {
    return std::max(low, std::min(high, value));
}
```

等价于：不小于 low、不大于 high。如果 value 在区间内就保持原样。

## 两个 Update 的重载

看头文件，`RectTracker` 有两个 `Update` 函数：

```cpp
void Update(const Detection& detection, ...);    // 接收 RKNN 的检测结果
void Update(const RefinedRect& rect, ...);       // 接收 ROI 精修的结果
```

两者实现几乎一样，都是调用 `ApplyMeasurement`：

```cpp
// Update from Detection
void RectTracker::Update(const Detection& detection, double timestamp,
                         const cv::Size& frame_size, const std::string& source) {
  ApplyMeasurement(detection.box, detection.center, detection.conf,
                   std::max(1, detection.candidate_count), timestamp, frame_size, source);
}

// Update from RefinedRect
void RectTracker::Update(const RefinedRect& rect, double timestamp,
                         const cv::Size& frame_size, const std::string& source) {
  ApplyMeasurement(rect.box, rect.center, rect.score, 1, timestamp, frame_size, source);
}
```

区别只有一个：`Detection` 的置信度用 `detection.conf`，候选数用 `detection.candidate_count`（最小为 1）；`RefinedRect` 的置信度用 `rect.score`，候选数固定为 1。其余逻辑完全一样。

`source` 参数分别标记为 `"rknn"` 或 `"refine"`，最终会通过 `Snapshot` 暴露给 `AimWriter`，写到输出里。这样你在外面就能知道"这一帧用的是 RKNN 直接结果还是精修后的结果"。

## 把状态机从头到尾走一遍

假设你是跟踪器，你经历了这样一个过程：

**帧 1**：你首次收到一个 RKNN 检测：
- `ApplyMeasurement` 被调用，`initialized_ == false`
- 直接初始化：位置 = 检测位置，速度 = 0，状态 → LOCKED

**帧 2**：你收到 RKNN 检测 + ROI 精修：
- `ApplyMeasurement` 再次被调用，`initialized_ == true`
- 帧 1 的速度是 0，所以预测位置和上一帧一样
- 残差 = 帧 2 的检测位置 - 帧 1 的检测位置
- α=0.55 融合位置，β=0.20 学到新速度，状态 → LOCKED

**帧 3-5**：正常跟踪，每帧都收到检测，位置和速度越来越准

**帧 6**：目标被树挡住，没检测到：
- 调用 `MarkDetectMiss`
- `misses_` 变成 1，调用 `Predict` 匀速外推位置
- 状态 → LOST（因为 misses_ > 0）
- 位置还在输出，但 `conf_ *= 0.97` 衰减

**帧 7-8**：还是没检测到，`misses_` 变成 2、3，继续预测

**帧 9**：`misses_` 变成 4，超过了 `max_predict_misses`（3）：
- `MarkDetectMiss` 内检测到超额
- 状态 → SEARCHING，`conf_ = 0`，`count_ = 0`
- 此后 `Snapshot().active == false`，AimWriter 知道没跟踪到有效目标

**帧 10**：目标重新出现，RKNN 检测到了：
- `Update` 被调用（`ApplyMeasurement` 被调用）
- 因为 `misses_ > max_predict_misses`，走初始化分支
- 全新初始化，速度归零，状态 → LOCKED，重新开始

## 新增语法：`std::clamp`

```cpp
const double dt = std::clamp(timestamp - last_timestamp_, 1e-3, 0.25);
```

`std::clamp` 是 C++17 `<algorithm>` 里新增的函数，行为等价于：

```cpp
// std::clamp(value, low, high) 等价于
std::max(low, std::min(high, value));
```

限制 value 在 [low, high] 闭区间。你项目的 `types.hpp` 里自己写了一个 `ClampFloat`，本质上就是 `std::clamp` 的浮点版本。

## 从 C 的角度看 RectTracker 类

如果你从 C 语言的角度看这个类，它本质上把下面的 C 代码封装了起来：

```c
// C 语言：散落的全局/静态变量
static float x_, y_, vx_, vy_, w_, h_;
static int misses_;
static bool initialized_;
static double last_timestamp_;

// C 语言：独立的函数
void RectTracker_Update(const Detection* det, double ts, int w, int h, const char* src) { ... }
void RectTracker_Predict(double ts, int w, int h) { ... }
Box RectTracker_PriorBox(void) { ... }
```

C++ 的 `class RectTracker` 把数据（成员变量）和操作（成员函数）打包在一起，而且每个跟踪目标可以有自己的实例（虽然你当前项目只有一个目标，但架构上支持多个——每个目标对应一个 `RectTracker` 实例）。

成员变量在 `private:` 下，意味着外部代码不能直接读 `tracker.vx_`，必须通过 `Snapshot()` 等公开接口访问。这就是**封装**。

## 小结

这章你学了一个完整的运动跟踪系统：

1. **α-β 滤波器的直觉理解**：
   - α（0.55）控制你对新测量值的信任度——越大越灵敏，越小越平滑
   - β（0.20）控制你学习目标速度的速率——比 α 小，保守学习
   - box_alpha（0.45）用指数移动平均平滑框的尺寸

2. **状态机**：SEARCHING → LOCKED → LOST → SEARCHING，清晰的生存周期

3. **ApplyMeasurement**：初始化/连续跟踪两个分支，位置修正 + 速度修正 + 尺寸平滑

4. **Predict 纯预测**：匀速模型 x += vx * dt，置信度衰减 3%/帧

5. **MarkDetectMiss**：丢帧计数，超过 3 帧回到 SEARCHING

6. **PriorBox**：跟踪器反馈给检测器的先验搜索区域

7. **Snapshot**：对外只暴露结构体，隐藏实现细节

8. **StepDt + Clamp**：时间差钳位（防除零、防跳变）+ 坐标钳位（防跑出画面）

`RectTracker` 只有 130 多行代码，却实现了一个完整的运动估计 + 丢帧处理 + 状态管理的系统。核心公式就两个：

```
位置:  x_new = x_pred + α × (x_meas - x_pred)
速度:  v_new = v_old + β × (x_meas - x_pred) / dt
```

记住这两个公式，你就理解了整个跟踪器在干什么。
