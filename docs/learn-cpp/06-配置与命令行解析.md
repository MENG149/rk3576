## 1. AppConfig 结构体——所有参数的"总开关"

打开 `include/rkfast/config.hpp`，你会看到一个巨大的 struct：

```cpp
namespace rkfast {

struct AppConfig {
  std::string model_path = "../../models/best_rk3576_int8.rknn";
  std::string camera = "/dev/video73";
  bool use_v4l2 = true;
  int width = 640;
  int height = 480;
  int fps = 60;
  std::string fourcc = "MJPG";

  int input_size = 640;
  int target_class = 0;
  int class_count = 2;
  float conf_threshold = 0.45f;
  float iou_threshold = 0.50f;
  int max_det = 1;
  float min_box_size = 6.0f;

  int warmup_runs = 3;
  std::string core_mask = "default";
  int detect_interval_locked = 2;
  int max_predict_misses = 3;
  float track_alpha = 0.55f;
  float track_beta = 0.20f;
  float track_box_alpha = 0.45f;

  float roi_expand_ratio = 0.24f;
  int roi_min_size = 24;
  float refine_min_area_ratio = 0.05f;

  bool show_window = false;
  double stats_interval = 1.0;
  int opencv_threads = 1;
  std::string main_affinity;
  std::string camera_affinity;
  std::string detector_affinity;

  std::string serial_port;
  int baudrate = 115200;
  double stdout_interval = 0.20;
  double serial_interval = 0.02;
};

}  // namespace rkfast
```

一眼看过去，这玩意儿就是一个"参数仓库"。每个字段对应项目运行时的某个可调选项。注意一个关键细节：**每个字段都有默认值**。这意味着即使用户不传任何命令行参数，程序也能用一组合理的默认值跑起来。

### 为什么用 struct 而不是 class？

你刚学过 class，可能想：为什么不把配置写成一个 class，把字段藏起来？

答案：配置就是纯数据，没有需要封装的内部逻辑。用 struct 就够了——省去 public: 标签，字段直接访问，一目了然。记住上一章说的：**struct 就是纯数据容器，class 是有复杂行为的对象**。

### C++11 的新语法：声明时给默认值

```cpp
// C 语言：声明时不赋值，必须后面手动初始化
struct Config {
    int width;
    int height;
};
struct Config c;
c.width = 640;    // 手动赋值
c.height = 480;   // 手动赋值

// C++：声明时直接给默认值（C++11 起支持）
struct AppConfig {
    int width = 640;    // ← 默认值直接写在声明处
    int height = 480;   // ← 不传就这个值
};
AppConfig config;   // 创建出来就有默认值，不用再手动设
```

这个特性叫**默认成员初始化器（default member initializer）**。你项目里到处都用，省去了写构造函数的麻烦。

## 2. 分组讲解参数

三十多个参数看起来吓人。按功能分组就清楚了：

### 2.1 模型参数

```cpp
std::string model_path = "../../models/best_rk3576_int8.rknn";  // RKNN 模型文件路径
int input_size = 640;        // 模型输入尺寸（640x640，YOLO 风格）
int target_class = 0;        // 我们要跟踪的目标类别编号
int class_count = 2;         // 模型总共能识别几类物体
```

`model_path` 指向 RK3576 NPU 的模型文件。`input_size` 是 640，意思是送进模型的图像会被缩放到 640x640——YOLO 系列模型的常见尺寸。`target_class = 0` 表示"我们关心第 0 号类别"，因为打靶场景通常只有一个目标类别（装甲板）。

### 2.2 相机参数

```cpp
std::string camera = "/dev/video73";  // 相机设备路径（Linux V4L2 设备文件）
bool use_v4l2 = true;                  // 是否优先使用 V4L2 API（嵌入式板子的标准）
int width = 640;                       // 采集分辨率：宽
int height = 480;                      // 采集分辨率：高
int fps = 60;                          // 目标帧率
std::string fourcc = "MJPG";          // 视频编码格式（四字符码）
```

`/dev/video73` 是 Linux 上的相机设备节点。`use_v4l2 = true` 表示优先用 V4L2——这是嵌入式 Linux 上工业摄像头的标准驱动框架。`MJPG` 是 MJPEG 格式的四字符码，压缩率高，适合高帧率传输。下一章 `camera_source.cpp` 会详细解释为什么要设置 FOURCC。

### 2.3 检测参数

```cpp
float conf_threshold = 0.45f;   // 置信度阈值：低于这个分数的框直接丢弃
float iou_threshold = 0.50f;    // NMS 的 IOU 阈值：重叠度超过 50% 就合并
int max_det = 1;                // 最多保留几个检测框（打靶只需要一个）
float min_box_size = 6.0f;      // 最小框尺寸：太小的框当作噪点忽略
```

这些参数控制 YOLO 后处理的 NMS（非极大值抑制）行为：
- `conf_threshold = 0.45`：模型输出的置信度低于 45% 的检测框，直接丢掉
- `iou_threshold = 0.50`：两个框的重叠比例超过 50%，保留置信度高的，丢掉那个低的
- `max_det = 1`：打靶场景永远只需要一个目标，设成 1 即可
- `min_box_size = 6.0`：6 像素以下的框直接丢掉（这种框肯定不是装甲板）

### 2.4 跟踪参数

```cpp
float track_alpha = 0.55f;       // α 滤波系数：位置平滑（越大越紧跟新值）
float track_beta = 0.20f;        // β 滤波系数：速度估计平滑（越大越跟随变化）
float track_box_alpha = 0.45f;   // 框尺寸的 α 滤波系数
int max_predict_misses = 3;      // 连续多少帧没检测到就认为目标丢失
int detect_interval_locked = 2;  // 锁定后每 N 帧做一次 ROI 检测
```

α-β 滤波器是经典的恒定速度滤波器，虽然还没学到，但你现在知道这几个参数的大致含义就行：
- `alpha` 控制"对当前测量值的信任程度"——大就紧跟检测结果，小就倾向于保持历史轨迹
- `beta` 控制速度估计的响应速度
- `max_predict_misses = 3`：如果连续 3 帧都没检测到目标，放弃当前轨迹

### 2.5 系统参数

```cpp
std::string main_affinity;       // 主线程绑定到哪个 CPU 核心
std::string camera_affinity;     // 相机采集线程绑定到哪个 CPU 核心
std::string detector_affinity;   // 推理线程绑定到哪个 CPU 核心
std::string serial_port;         // 串口设备路径（如 /dev/ttyTHS1）
int baudrate = 115200;           // 串口波特率
double stdout_interval = 0.20;   // 终端输出的时间间隔（秒）
double serial_interval = 0.02;   // 串口发送的时间间隔（秒）
bool show_window = false;        // 是否显示 CV 窗口
int opencv_threads = 1;          // OpenCV 内部线程数
```

CPU affinity（亲和性）是多核嵌入式系统常用的优化手段：把采集线程、推理线程、主循环线程分别绑在不同的 CPU 核心上，避免线程切换带来的缓存失效和延迟抖动。

`stdout_interval = 0.20` 表示每 0.2 秒往终端输出一次状态——不是每帧都输出（太快了，60fps 每帧都打的话终端会卡）。

## 3. 为什么用 struct 存配置而不是全局变量

你刚学会 C 语言时，很可能这样写配置：

```c
// C 风格：一堆全局变量散落各处
char model_path[256] = "../../models/best_rk3576_int8.rknn";
int width = 640;
int height = 480;
int fps = 60;
float conf_threshold = 0.45f;
float iou_threshold = 0.50f;
// ... 散落在 main.c 最上面
```

这种方式有几个致命问题：

**问题1：不知道哪些变量是配置。** `int width` 可能是配置，也可能是个临时变量。没有结构化信息。

**问题2：想传配置给某个函数？传一堆参数。**

```c
// C 风格：每个函数要把所有需要的参数列出来
void init_camera(char* device, int width, int height, int fps, char* fourcc, ...);
//               ↑ 参数列表越来越长，改一个参数要改所有函数签名

// C++ 风格：传一个 AppConfig 引用就行
void init_camera(const AppConfig& config);
//               ↑ 加了新参数？改 struct 就行，函数签名不需要动
```

**问题3：全局变量可以在任何地方被修改。** 你不知道谁改了它，调试时非常痛苦。

**问题4：默认值不直观。** 全局变量声明时不能给值（C89 不允许），你得在 main 开头一堆赋值。

**struct 方案的优势：**
- 所有参数打包在一起，一传整包
- 默认值写在声明处，一眼看清
- 用 `const AppConfig&` 传参，接收方只读，不能改
- 加新参数只改一处（struct 定义），不改函数签名

这就是为什么哪怕只是存数据，一个 struct 也比散落的全局变量好一万倍。

## 4. ParseCommandLine 函数精讲

这是本章的技术核心。打开 `src/config.cpp`：

```cpp
bool ParseCommandLine(int argc, char** argv, AppConfig* config) {
  if (config == nullptr) {
    return false;               // 空指针直接返回，防止崩溃
  }
  for (int i = 1; i < argc; ++i) {
    const std::string arg = argv[i];
    std::string value;
    // ... 一大串 if-else
  }
  return true;
}
```

### 4.1 argc / argv 回顾

你应该还记得 C 语言里的 `main(int argc, char** argv)`：

```
命令行：./rkfast --model a.rknn --width 1280 --height 720

argc = 7   ← 参数总数（包括程序名本身）
argv[0] = "./rkfast"
argv[1] = "--model"
argv[2] = "a.rknn"
argv[3] = "--width"
argv[4] = "1280"
argv[5] = "--height"
argv[6] = "720"
```

循环从 `i = 1` 开始，跳过 argv[0]（程序名）。

### 4.2 命令行循环结构

```cpp
for (int i = 1; i < argc; ++i) {
    const std::string arg = argv[i];   // 把 C 字符串转成 std::string
    std::string value;                  // 存放参数值

    if (arg == "--help" || arg == "-h") {
      PrintUsage(argv[0]);
      return false;        // 打印帮助后退出，不继续运行
    }
    if (arg == "--model") {
      if (!NeedValue(argc, argv, &i, &value)) return false;
      config->model_path = value;   // 把参数值存入配置
    } else if (arg == "--width") {
      if (!NeedValue(argc, argv, &i, &value)) return false;
      config->width = std::stoi(value);   // string → int
    }
    // ... 更多参数
}
```

整个逻辑是一串 `if-else if`：
1. 判断当前 `argv[i]` 是哪个参数名（如 `--width`）
2. 调用 `NeedValue` 把下一个 `argv[i+1]` 读出来
3. 做类型转换（如果需要），存入 `config` 对应的字段
4. 如果参数不需要值（如 `--window`），直接设置布尔值

### 4.3 NeedValue 辅助函数

```cpp
namespace {    // ← 匿名 namespace，相当于 C 里的 static

bool NeedValue(int argc, char** argv, int* index, std::string* value) {
  if (*index + 1 >= argc) {    // 下一个参数存在吗？
    std::cerr << "Missing value for " << argv[*index] << "\n";
    return false;               // 没有就报错
  }
  *value = argv[++(*index)];   // 把 index 往前移一位，取出值
  return true;
}

}  // namespace
```

这个函数做了两件事：
1. **安全检查**：如果 `--width` 后面没东西了（用户只写了 `--width` 没写数字），立刻报错
2. **指针自增**：`argv[++(*index)]` 同时做了两件事——把 `i` 加 1，然后取出 `argv[i]`

为什么要自增 `index`？因为外面的 for 循环还会再 `++i`，如果 NeedValue 不自增，循环会把参数值（如 `"1280"`）当成下一个参数名去匹配。

**图解：**

```
argv = ["./rkfast", "--width", "1280", "--fps", "60"]
                       i=1       i=2       i=3     i=4

进入循环 i=1，识别到 "--width"
→ NeedValue: index 从 1 变成 2，取出 "1280"
→ 循环 ++i：i 变成 3，跳过已处理的 "1280"
→ 接下来 argv[3] = "--fps"，继续解析
```

### 4.4 匿名 namespace 的含义

```cpp
namespace {    // 没有名字的 namespace
  bool NeedValue(...) { ... }
}
```

匿名 namespace 里的东西**只在当前 .cpp 文件内可见**。等价于 C 语言的 `static` 函数。Why？因为 `NeedValue` 只是 `config.cpp` 内部用到的小辅助函数，不需要暴露给其他文件——最小化接口原则。

### 4.5 std::stoi / stof / stod —— 字符串转数字

这是 C++11 引入的类型转换函数，比 C 的 `atoi` / `atof` 安全：

```cpp
config->width       = std::stoi(value);   // String TO Int:     "1280" → 1280
config->height      = std::stoi(value);   // String TO Int:     "720"  → 720
config->fps         = std::stoi(value);   // String TO Int:     "60"   → 60
config->conf_threshold = std::stof(value); // String TO Float:  "0.45" → 0.45f
config->iou_threshold  = std::stof(value); // String TO Float:  "0.50" → 0.50f
config->stdout_interval = std::stod(value); // String TO Double:"0.20" → 0.20
config->serial_interval = std::stod(value); // String TO Double:"0.02" → 0.02
```

| 函数 | 全称 | 输入 | 输出 | 你项目里转换了什么 |
|------|------|------|------|-------------------|
| `std::stoi` | String TO Int | `"1280"` | `1280` | width, height, fps, max_det, baudrate |
| `std::stof` | String TO Float | `"0.45"` | `0.45f` | conf, iou, track_alpha, track_beta |
| `std::stod` | String TO Double | `"0.20"` | `0.20` | stdout_interval, serial_interval, stats_interval |

为什么浮点数有两种（float/double）？`float` 是 32 位单精度，`double` 是 64 位双精度。配置里 track_alpha 这种精度要求不高的用 float，时间间隔用 double——精度要求稍高一些。实际差别不大，知道有这个区分就行。

与 C 的对比：

```c
// C 语言做法：atoi / atof（有缺陷：不报错，返回 0 无法区分是"真的 0"还是"转换失败"）
int width = atoi("1280");   // 返回 1280
int bad   = atoi("abc");    // 返回 0，但你没法知道是"转换失败"还是真的是 0

// C++ 做法：std::stoi 遇到 "abc" 会抛出异常（std::invalid_argument）
int width = std::stoi("1280");   // 返回 1280
int bad   = std::stoi("abc");    // 抛出异常，程序可以捕获并报错
```

### 4.6 --window 和 --no-window：布尔开关

这两个参数不需要取值：

```cpp
} else if (arg == "--window") {
    config->show_window = true;       // 直接设 true，不需要 NeedValue
} else if (arg == "--no-window") {
    config->show_window = false;      // 直接设 false
}
```

它们是"开关型参数"——出现了就生效，不需要后面的值。和 `--width 640` 这种"键值型参数"不同的处理方式。

### 4.7 core_mask 的值校验

```cpp
} else if (arg == "--core-mask") {
    if (!NeedValue(argc, argv, &i, &value)) return false;
    if (value != "default" && value != "auto" && value != "0" &&
        value != "1" && value != "01" && value != "all") {
      std::cerr << "Invalid --core-mask: " << value << "\n";
      PrintUsage(argv[0]);
      return false;
    }
    config->core_mask = value;
}
```

注意这里多了一步**值范围校验**：不是随便传什么字符串都能通过。如果用户传了不在白名单里的值（如 `--core-mask 99`），程序会报错并打印帮助。这是健壮性（robustness）的体现——在解析阶段就拦掉非法输入，而不是等运行到一半才崩溃。

### 4.8 未知参数的兜底

```cpp
} else {
    std::cerr << "Unknown option: " << arg << "\n";
    PrintUsage(argv[0]);
    return false;
}
```

所有 if-else 都没匹配上，说明用户打了错别字或者不存在的参数。打印错误 + 帮助信息，返回 false 让 main 退出。

## 5. PrintUsage 函数

```cpp
void PrintUsage(const char* argv0) {
  std::cout
      << "Usage: " << argv0 << " [options]\n"
      << "  --model PATH\n"
      << "  --camera DEVICE_OR_INDEX\n"
      << "  --width N --height N --fps N --fourcc MJPG\n"
      << "  --input-size N --class-count N --target-class N\n"
      << "  --conf F --iou F --max-det N --min-box-size F\n"
      << "  --core-mask default|auto|0|1|01|all\n"
      << "  --detect-interval-locked N --max-predict-misses N\n"
      << "  --main-affinity LIST --camera-affinity LIST --detector-affinity LIST\n"
      << "  --serial-port PATH --baudrate N\n"
      << "  --window | --no-window\n";
}
```

这跟 C 语言里写 `printf` 打印帮助信息一样，只不过用了 C++ 的 `std::cout` 流输出。`<<` 是流插入运算符，可以链式拼接。

注意参数说明里用 `N` 表示整数、`F` 表示浮点数、`PATH` 表示路径——这是帮助文档的常见约定。

## 6. C vs C++ 命令行解析对比

如果用纯 C 写同样的功能：

```c
// C 风格命令行解析（伪代码，省略了大量边界检查）
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

char model_path[256] = "../../models/best_rk3576_int8.rknn";
int width = 640;
int height = 480;

int parse_args(int argc, char** argv) {
    for (int i = 1; i < argc; i++) {
        if (strcmp(argv[i], "--model") == 0) {      // C 用 strcmp 比较字符串
            if (i + 1 >= argc) { printf("Missing value\n"); return 0; }
            strcpy(model_path, argv[++i]);           // C 用 strcpy 拷贝字符串
        } else if (strcmp(argv[i], "--width") == 0) {
            if (i + 1 >= argc) { printf("Missing value\n"); return 0; }
            width = atoi(argv[++i]);                 // C 用 atoi，不报错
        } else if (strcmp(argv[i], "--conf") == 0) {
            if (i + 1 >= argc) { printf("Missing value\n"); return 0; }
            // C 的 atof 没有 stof 安全
            conf_threshold = (float)atof(argv[++i]);
        }
        // ... 每加一个参数，要重复写 if (i+1>=argc) + strcmp + atoi/atof
    }
    return 1;
}
```

对比 C++ 版本：

| 方面 | C 风格 | C++ 风格 |
|------|--------|----------|
| 字符串比较 | `strcmp(a, b) == 0` | `a == b`（直观） |
| 字符串拷贝 | `strcpy(dst, src)` + 担心溢出 | `assign` 或 `=`（安全） |
| 字符串转整数 | `atoi()` 不报错 | `std::stoi()` 异常可捕获 |
| 字符串转浮点 | `atof()` 返回 double | `std::stof()` 返回 float |
| 值校验 | 手动 if-else 一堆 | 同样手动（std 没提供） |
| 代码量 | 每加一个参数重复写安全检查 | 用 NeedValue 封装了安全检查 |

核心差异：C++ 的 `std::string` 让字符串操作变得像整数一样直观，`==` 比较、`=` 赋值、`+` 拼接，不需要记 `strcmp`/`strcpy`/`strcat`。

## 7. 速查表

| 概念 | C 写法 | C++ 写法 | 出现在 config.cpp 哪里 |
|------|--------|----------|----------------------|
| 参数存储 | 散落全局变量 | `struct AppConfig` 集中管理 | config.hpp |
| 字符串比较 | `strcmp(a,b)==0` | `arg == "--model"` | 所有 if 分支 |
| 字符串→整数 | `atoi("1280")` | `std::stoi("1280")` | width, height, fps |
| 字符串→浮点 | `(float)atof("0.45")` | `std::stof("0.45")` | conf, iou, track_alpha |
| 字符串→双精度 | `atof("0.20")` | `std::stod("0.20")` | stdout_interval 等 |
| 局部函数 | `static bool need_value(...)` | 匿名 `namespace { ... }` | NeedValue |
| 空指针检查 | `if (p == NULL)` | `if (config == nullptr)` | ParseCommandLine 开头 |
| 终端输出 | `printf(...)` | `std::cout << ...` / `std::cerr << ...` | PrintUsage / 错误提示 |

---

## 8. 小结

这一章的核心收获：

1. **AppConfig struct = 参数总开关。** 所有配置打包进一个结构体，默认值写在声明处，用 `const AppConfig&` 只读传参。
2. **struct > 全局变量。** 集中管理、只读传递、加新参数不影响函数签名。
3. **命令行解析 = argc/argv 循环 + 字符串匹配 + 类型转换。** 核心模式就三步：匹配参数名 → 取下一个参数值 → 转类型存进 config。
4. **NeedValue 是封装出来的安全检查。** 避免每个分支重复写"下一个参数是否存在"的判断。
5. **std::stoi/stof/stod 比 atoi/atof 安全。** 真遇到非法输入，C++ 版本会抛出异常而不是悄悄返回 0。

## 9. 练习：写一个自己的命令行解析器

在电脑上新建 `practice_config.cpp`，实现一个简化版的配置解析：

```cpp
#include <iostream>
#include <string>

// ===== 第一步：定义配置结构体 =====
struct MyConfig {
    std::string name = "guest";
    int age = 18;
    float score = 0.0f;
};

// ===== 第二步：写 NeedValue 辅助函数 =====
bool NeedValue(int argc, char** argv, int* index, std::string* value) {
    if (*index + 1 >= argc) {
        std::cerr << "Missing value for " << argv[*index] << "\n";
        return false;
    }
    *value = argv[++(*index)];
    return true;
}

// ===== 第三步：写命令行解析函数 =====
bool ParseArgs(int argc, char** argv, MyConfig* config) {
    for (int i = 1; i < argc; ++i) {
        std::string arg = argv[i];
        std::string value;

        if (arg == "--name") {
            if (!NeedValue(argc, argv, &i, &value)) return false;
            config->name = value;
        } else if (arg == "--age") {
            if (!NeedValue(argc, argv, &i, &value)) return false;
            config->age = std::stoi(value);
        } else if (arg == "--score") {
            if (!NeedValue(argc, argv, &i, &value)) return false;
            config->score = std::stof(value);
        } else {
            std::cerr << "Unknown option: " << arg << "\n";
            return false;
        }
    }
    return true;
}

// ===== 第四步：测试 =====
int main(int argc, char** argv) {
    MyConfig config;
    if (!ParseArgs(argc, argv, &config)) {
        return 1;
    }
    std::cout << "Name:  " << config.name  << "\n";
    std::cout << "Age:   " << config.age   << "\n";
    std::cout << "Score: " << config.score << "\n";
    return 0;
}
```
