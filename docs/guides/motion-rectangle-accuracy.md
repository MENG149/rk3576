# 运动场景矩形识别准确率优化建议

日期：2026-07-13

本文记录后续提升“运动时精准识别矩形”的优化方向。当前项目已经具备 RKNN 检测、ROI 矩形精修、Kalman 运动预测和目标平面估计，本指南只记录后续可改进项，不代表这些优化已经全部实现。

## 当前已具备能力

- RKNN 负责目标发现、重捕获和低频校正。
- ROI 精修在已有检测框或 prior box 内进行矩形边缘/轮廓精修。
- Kalman tracker 已用于中心、速度和尺寸预测。
- 主循环每帧先预测，再使用当前帧 ROI 精修结果或 RKNN 结果更新 tracker。
- 120 FPS 相机接入后，推荐让 ROI 精修和 Kalman 承担高频输出，RKNN 作为较低频锚点校正。

## 优化目标

运动时重点不是只提高 bbox 检测置信度，而是提高四个角点和矩形中心在时间序列上的稳定性。

建议关注以下指标：

- 检出率：运动时不能频繁掉锁。
- 中心误差：中心点不能明显偏离真实矩形中心。
- 四角抖动：目标连续运动时四角不应随机跳动。
- 延迟：输出位置不能明显滞后目标。
- 重捕获速度：ROI 失败或遮挡后，RKNN 能快速重新锁定。

## 优先级 1：先保证运动画面清晰

运动识别不准时，首先排查成像质量。若边缘已经被运动模糊抹掉，后续算法只能猜。

建议：

- 使用短曝光 / 高快门。
- 增加补光，避免高快门导致画面过暗。
- 优先使用全局快门相机，降低滚动快门形变。
- 固定曝光、增益、白平衡，避免自动曝光在运动中跳变。
- 目标矩形边缘保持高对比度，例如黑白边框。
- 固定焦距，避免自动对焦抖动。

## 优先级 2：ROI 精修升级为四边直线拟合

当前 ROI 精修可以继续增强。后续建议从“框级/轮廓级”升级为“四边/四角级”测量。

推荐流程：

```text
Kalman 预测 ROI
-> 在 ROI 内做边缘提取
-> 拟合四条主边直线
-> 四条直线求交得到四个角点
-> 用矩形几何约束过滤异常
-> 输出 refined corners / center / score
```

建议加入的几何约束：

- 对边近似平行。
- 边长比例接近真实目标比例。
- 面积不能相邻帧突变。
- 中心不能瞬间跳太远。
- 四角顺序不能翻转。
- 透视变形需要在合理范围内。
- ROI 精修分数低时，不强行更新 Kalman。

这个方向不依赖重新训练模型，适合优先实现。

## 优先级 3：增加角点级预测或单应性预测

现有 Kalman 主要跟踪中心、速度和尺寸。若后续要求“矩形角点非常稳”，可以增加角点级时序状态。

推荐两层结构：

```text
中心/尺寸 Kalman：负责粗定位 ROI
四角/单应性预测：负责精确矩形姿态
```

可选实现：

- 直接对四个角点分别做滤波。
- 对目标平面 homography 做时序预测。
- 以上一帧四角作为当前帧 ROI 精修的角点先验。

收益：

- 运动中角点更稳。
- RKNN 结果延迟时，可以用预测角点减少滞后。
- ROI 精修更不容易被局部边缘噪声带偏。

## 优先级 4：加入 KLT 光流辅助

120 FPS 场景下，相邻帧位移通常较小，光流可以作为两次 RKNN 之间的快速角点初值。

推荐流程：

```text
上一帧四角/边缘采样点
-> KLT 光流跟踪到当前帧
-> 用光流结果初始化四边搜索
-> ROI 精修重新贴边
-> Kalman 融合输出
```

定位：

- 光流不是最终结果。
- 光流用于给 ROI 精修提供更好的初值。
- ROI 精修失败或光流漂移时，回退到 Kalman prior 或 RKNN 重捕获。

## 优先级 5：训练数据加入运动退化

如果 RKNN 在运动时重捕获不稳定，需要从数据侧增强。

建议加入：

- 运动模糊增强。
- 亮度变化。
- 曝光不足。
- 目标靠边。
- 部分遮挡。
- 不同距离和不同透视角度。
- 真实 120 FPS 相机采集的视频帧。

如果继续使用 bbox 模型，训练集至少要覆盖运动模糊场景。否则运动中一旦 ROI 丢失，RKNN 也可能无法稳定重捕获。

## 优先级 6：模型输出从 bbox 升级为角点

普通 YOLO bbox 适合发现目标，但不适合直接输出高精度矩形角点。

后续可选模型路线：

1. 普通 bbox 模型  
   简单、速度快，但角点精度依赖后处理。

2. OBB / 旋转框模型  
   对倾斜矩形更友好，但仍不是精确四角。

3. 四角关键点模型  
   直接输出矩形四个角点，最适合云台精准瞄准。推荐作为长期方案。

推荐长期组合：

```text
RKNN 四角关键点模型
-> ROI 四边直线精修
-> Kalman / 光流时序融合
```

## 120 FPS 相机接入后的测试重点

接入 120 FPS 相机后，不要只看 RKNN FPS，要同时观察主循环、ROI 和跟踪状态。

运行示例：

```bash
bash run_camera.sh --fps 120
```

如果 RKNN 提交过密，可以测试：

```bash
bash run_camera.sh --fps 120 -- --detect-interval-locked 1
bash run_camera.sh --fps 120 -- --detect-interval-locked 2
```

重点观察日志：

```text
frame_fps
detector_hz
infer_capacity
refine
loop
overwritten
measurement_age
state
source
conf
```

判断标准：

- `frame_fps` 接近 120：相机和主循环能跑满。
- `source=roi` 或 `source=roi+rknn`：ROI 精修正在承担高频跟踪。
- `refine + loop < 8.3ms`：每帧处理时间满足 120 FPS。
- `overwritten` 很多：RKNN 提交频率超过 detector 能力，需要增大 `detect-interval-locked`。
- `measurement_age` 持续变大：测量滞后，需要降低 RKNN 频率或增强 ROI。
- `state` 经常掉到 `SEARCHING/LOST`：重捕获或 ROI 稳定性不足。

## 参数调试方向

可优先调试这些参数：

```text
--detect-interval-locked
--kalman-process-noise
--kalman-roi-noise
--kalman-rknn-noise
--kalman-gate
--motion-roi-gain
--motion-speed-ref
```

调参原则：

- 目标速度越快，ROI 应适当扩大。
- RKNN 结果越旧，RKNN 测量噪声应越大。
- ROI score 低时，不应强行校正 Kalman。
- 连续 ROI 失败时，应提高 RKNN 重捕获频率。
- Kalman 太稳会滞后，太灵敏会抖动，需要用运动视频调平衡。

## 推荐实施顺序

后续如果要实际改代码，建议按以下顺序做：

1. 用 120 FPS 相机采集运动视频，并保存每帧输出日志。
2. 分析主要失败类型：ROI 找不到、四角跳动、RKNN 重捕获慢、运动模糊、Kalman 滞后。
3. 实现运动自适应 ROI。
4. 实现四边直线拟合和几何约束。
5. 增加角点级时序滤波或 homography 预测。
6. 需要时加入 KLT 光流初值。
7. 若 RKNN 重捕获仍不稳，再补运动退化数据并考虑关键点模型。

优先推荐的第一项代码改造：

```text
运动自适应 ROI + 四边直线拟合 + 四角时序滤波
```

这是最贴合当前 RKNN + ROI + Kalman 架构的路线，不需要立刻重训模型，风险较低，收益直接。
